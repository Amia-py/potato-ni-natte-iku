## 2. 技术栈

纯 Python + OpenGL（moderngl）+ 自写 GLSL 着色器实时渲染，逐帧导出后由 ffmpeg 编码。没有用任何视频模板软件或后期软件，所有画面元素都是程序化生成的。

- 渲染驱动：`render.py`（`stills` / `sheet` / `video` 三种模式）
- 引擎层：`engine/`（GL 封装、绘制、文字图集、Live2D 绑定、动作采样）
- 编排层：`director/`（镜头表 `shots_new.py`、排版层 `typo.py`、歌词时间轴、音频分析）
- 字体：`fonts/`（OFL 授权的显示字面）+ 系统 Noto / Consolas
- 着色器：`shaders/`（20 个 GLSL 文件：16 个 `.frag` + 3 个 `.vert` + `common.glsl`）

## 3. 核心设计

### 3.1 编排模型

全片按小节（bar）切分镜头，116 BPM，每小节 2.069 秒。`director/shots.py` 里的 `build_shots()` 产出一个镜头表，每项含 `t0/t1/fn/trans`。`frame(t)` 查表找到当前镜头并调用，返回值可覆盖后处理参数。

镜头之间支持 5 种转场（`wipe.frag` 的 `uMode`），转场期间前后两个镜头各渲染到独立 FBO，再混合。

### 3.2 角色图层

Live2D 角色（天马司 / 凤笑梦 / 草薙宁宁 / 神代类 / 初音未来）用 Cubism 运行时逐帧渲染到各自 FBO，再作为精灵贴到主画布。物理、眨眼、口型都是运行时驱动的。

`MV.cast()` 是一个有序迭代器，决定一排角色的绘制次序：先画初音未来的猫尾巴（`miku_tail`），再按 `ROSTER` 顺序画其他角色，初音本体最后。这样保证初音头发压在宁宁之上、而归尾落在宁宁之下。

猫尾巴之所以要单独拆出来，是因为它在原模型里和身体同属 `PartBody2`，无法在部件级分离。做法是从贴图图集里按连通域切出尾巴那一块，生成两份模型：

- `D:\MV_DS\assets_miku_split\notail\` — 除尾巴外的全部
- `D:\MV_DS\assets_miku_split\tailonly\` — 只有尾巴

**这两个目录是运行时依赖，不能删除。**

### 3.3 2D 土豆

`potatoes.frag` 把土豆画成 2D 精灵：程序化 SDF 凹凸轮廓、贴纸式粗描边、两阶平涂（亮面 + 新月形暗面）、短弧高光加圆点高光。脸型（圆眼 / 弯月眼 / 眯眼三种眼睛，配三种嘴）由土豆自己的种子决定，会眨眼，转身时脸在身体上滑动。南瓜灯款是星星眼 + 锯齿笑嘴。

深度排序用画家算法取最近两层做透明混合。

### 3.4 线稿版（当前）

卡面与人物不再上色，全部转成线稿：

- `engine/lineart.py`：带限梯度 + 阈值 + 膨胀，输出「墨色线条 + 透明底」的 RGBA，落到 `work/lineart/` 缓存，按源文件与参数做键。卡面用 `thick=3`（大图缩到屏上需要更粗的线），立绘用 `thick=2`。
- 图版一律按原始宽高比摆放（`plate()` 只给最大框，不拉伸），`full()` 走 `cover`，所以人物不会被压扁。
- 深色页把线稿用 `uTint` 反成奶油色，纸底仍是暖褐片基。
- 歌词统一为**右边缘细竖排**：字号固定 24，纵距 1.5，逐字扫色；所有歌词行都出现，位置不随页面变化——这一条对齐官方 V 版的做法。
- 角色介绍五页改为「线稿剧照 + 黑色名牌 + 齿孔条」，名牌取自官方 V 版角色卡的样式。
- 转场换成胶片语汇：`wipe.frag` 的 `uMode` 6=烧穿、7=纵向滑移、8=闪光切、9=快门条。
- 土豆重画：梨形轮廓 + 三个芽眼 + 高光眼睛 + 微笑，`potato_ink.frag`。

### 3.5 与上一版的差异

第一版是深棕金复古舞台 + 2D 土豆 + Live2D 拼贴；第二版走到另一个极端，是冷峻的印刷单色版；当前版回到复古，但走电影调——暖褐片基、彩色卡面、文字退到画面之后。三轮下来镜头表都在 `shots_new.py`，靠 `FILM` 基调与 `plate()`/`full()` 两个函数控制整片质感，换风格只需改这两处与配色表。

### 3.6 铅格风重制（当前）

参照《虚无小姐》2DMV 铅格风与官方 V 版两支片子的剪辑语言重做：

- **角色介绍页**改用本活动卡面线稿（`card_ln`，阈值 `lo .20 / hi .46`、连通域 `min_frac .035`、中心权重 `focus 1.4`）。卡面本身带背景，所以每页套一个图版框、压一层纸色薄雾，把残余线条读成印刷底纹而不是噪点。
- **正文页只出现正在唱的人。** `cast(t)` 逐帧读 `lyrics_timing.json` 的 `singers` 字段，把日文名映射到 `rui / tsukasa / nene / emu / miku`，只有这些角色被画进画面；器乐段无人可画，就只放道具。
- **30 张手绘线稿接入。** `gen_ln(who, k)` 读 `work/lineart_src/{who}_{n}.png`，镜头序号决定姿势，同一姿势不会连着出现两次。之前只接了 5 张、且只用在介绍页，等于没用上。
- **道具层 `director/props.py`。** 二十种可绘制元素：幕布、聚光灯锥、地板、麦克风、音箱、灯串、观众剪影、纸屑、音符、时钟、木箱、梯子、绳索、蒸汽、齿轮、胶片条、票根、雨、窗、飘纸。全片每页至少三件，用来填掉原来的大片留白。
- **歌词五套版式轮换**（每三小节换一次）：贴边竖排 52、双列阶梯 46、横排右对齐 48、单字巨排 70、双行横排 46。全部落在画面右半，不会压到人。
- **转场**：`wipe.frag` 新增 10 横向切片滑移、11 反色闪、12 网格溶解、13 横向推进；配原有的烧穿、纵向滑移、闪光切、快门条共用。
- **方格纸底**：`paper.frag` 新增 `uGrid`，34px 格子加每五格加重线，做铅格风的纸底。

### 3.8 全片复查修掉的四处

1. **角色每帧换姿势**（严重）：`next_pose()` 原来在每帧被调用，同一个镜头里人物一秒换 60 张画，屏录里看到的就是这个闪动。改为 `held_pose()`：每个镜头、每个角色、每个槽位只取一次，取完固定。
2. **歌词竖排上下被裁**：字号只按高度的 90% 算，长句仍会顶出画面。改为按 `H*.87` 反算字号，并把整列从右边缘内移到 `W-132`，不再压到版心框上。
3. **歌词版式在镜头中间跳变**：版式原来按小节轮换，一个镜头里会从两列突然变成一列。改为按镜头号取模。
4. **文字重复与越界**：38 秒页原本把歌词同时当大标题又当歌词画了两遍，改成「幕間」；结尾署名 64 号超出画幅被左右切掉，降到 46 号。

另外重画了麦克风（原来只有一个杆加方块），并给舞台页加了第二支麦、灯泡、木箱。

### 3.9 自动复查手段

`potato_MV_debug.mp4` 生成后按 10fps 抽样 1875 帧，逐帧算灰度差：全片中位帧差 0.75、95 分位 3.08，唯一超过 12 的孤立跳变在 97.3 秒，正好是镜头切点。也就是说镜头内部不再有突跳，剩下的差异全部来自转场。

## 5. 运行方式

所有命令里的 `python` 指 `D:\Python311\python.exe`。本机 PATH 上排第一的 `python` 是 3.13，没装下面这些依赖，直接跑会报 `ModuleNotFoundError`。

```bash
cd D:/MV_DS/mv

# 渲染指定时间点的静帧 → D:/MV_DS/work/stills/f_<t>.png
python render.py stills 7.2 73.5 157.5

# 联系方式图 → D:/MV_DS/work/sheet.jpg
python render.py sheet 0 20 12

# 渲染整片
python render.py video D:/MV_DS/output/potato_MV.mp4

# 只渲染某一段
python render.py video out.mp4 130 165
```

依赖：`moderngl`、`Pillow`、`numpy`、`scipy`、`imageio-ffmpeg`、`live2d-py`，以及带 CUDA 的 NVENC（编码器写死在 `render.py` 的 `nvenc` 分支）。

## 7. 已知限制

- 渲染速度约 90–100 帧/秒（1080p60），整片约 2 分钟。
- 编码器固定为 `h264_nvenc`，换到没有 NVIDIA GPU 的机器上需要改 `render.py` 的编码参数。
- 角色镜头在 `uRetro` 较高时肤色会偏灰，当前值 0.5 是实测的平衡点。
- 猫尾巴拆分依赖贴图图集的连通域编号（尾巴是第 57 号），换模型需要重新定位。
