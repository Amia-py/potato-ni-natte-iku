## 〇、最重要的一章：基于此继续创作时，如何给 Agent 写提示词

这一章是写给「下一个拿着这个仓库继续做 MV 的人」的。你已经有一个能跑的完整工程，此时对 Agent 说的话决定了它是「在既有体系里做增量」还是「推倒重来把风格搅乱」。以下是经过整个项目打磨出来的方法论，按重要程度排序。

### 0.1 第一原则：告诉 Agent 它接手的是一个「已经定稿的视觉体系」

不要只说「帮我加一个分镜」。要说清楚：**本工程有一套已锁定的视觉语言，新内容必须并入，不得另起炉灶**。推荐的开场白模板：

```
本项目是已完成的 MV 工程（详见 README）。所有视觉决策——纸底铅格、
复古电影调 FILM 基调、线稿人物、右缘歌词、道具至少三件每页——都是定稿。
本次任务：______。要求：只做增量修改，不改动以下文件/参数：______。
完成后用 python render.py stills 抽帧自查，再告诉我检查了什么。
```

### 0.2 指令的颗粒度：一次一个分镜，逐个验收

这个项目最大的教训是：**批量指令会让 Agent 用同一套便宜方案糊满全片**。早期一句「重设计 5 个角色介绍分镜」，结果五页呈现雷同、留白过大。后来改成「逐个分镜调整，每页呈现方式必须不同」，质量立刻上去。所以：

- 一次下达 **1～3 个分镜** 的修改指令，看完抽帧确认，再给下一批；
- 每条指令点名 **具体分镜名**（`s_v1a`、`s_chorus3`、`s_end`……见第十一章分镜表），不要说「那个副歌的地方」；
- 要求 Agent 交付时附 **抽帧截图或 contact sheet**（`python render.py sheet t0 t1 n out.jpg`），你只审图，不读代码。

### 0.3 用「负面清单」锁住你不许被动的部分

Agent 天生手痒。它看到可以优化的东西就会顺手改。必须显式列出禁区，例如本项目实际用过的负面清单：

```
禁止事项：
1. 歌词永远固定在画面右缘，不许改到左侧或居中；
2. 人物只允许出现在左半屏（cx ≤ W*0.40），宽不超过 W*0.52；
3. 歌词与人物不得同侧——这是铁律，违反即重做；
4. 不许动 EXTRA_TEXT 字集白名单之外引入新字符（缺字会静默消失）；
5. speaker tag 严禁触碰对话正文（歌词逐字时间轴不可手改）；
6. 不许引入新的第三方依赖。
```

**经验：负面清单比正面描述有效十倍。**「歌词要好看」没有约束力，「歌词不得与人物同侧」才有约束力。

### 0.4 要求 Agent「自查后再交付」，并让它报告证据

每轮迭代结尾固定加一句：

```
完成后：
1. 用 render.py stills 渲染受影响分镜的代表帧；
2. 自己先检查：同侧冲突、留白比例、歌词大小、呈现创意是否与相邻页雷同；
3. 报告你检查了哪些帧、发现了什么问题、改了什么。
不要只说"已完成"。
```

本项目后期所有「屏录闪动」「歌词重复」「幕布合不拢」类 bug，都是靠强制自查抽帧提前暴露的。Agent 不自查，你就成了人工 QA，一轮迭代要来回三遍。

### 0.5 参考物要具体到「可指认的视觉特征」

「参考官方 MV」是无效指令。有效指令长这样：

```
转场参照《虚无小姐》的铅格风与官方 V 版两支片：
- 铅格风 = 转场边缘用墨色细线勾边，不用彩色光晕；
- 官方 V 版 = 快速的遮罩形状切换（星形/圆形/闸刀），单次转场 ≤ 0.3 秒。
```

把参考拆成 **可实现的视觉特征**（形状、颜色、时长、运动方向），Agent 才能落到 shader 参数上。

### 0.6 出图类任务（线稿、卡面）的专用提示词模式

本项目 37 张姿势线稿全部由图像模型「以官方卡面为参考画线稿」产出，不是算法提取。算法提取（梯度边缘）试过，头发丝和背景杂物全糊在一起。给图像模型的提示词要点：

```
以这张卡面为参考，画一张干净的黑白线稿：
- 只保留人物和她直接接触的物品（手机、机器人、熊猫等），无背景；
- 线条简洁统一，闭合区域不上色；
- 人物完整：五官齐全，不缺胳膊少腿，姿势与卡面一致；
- 白底黑线，输出 PNG。
```

三条铁律，血泪换来的：

1. **「接触物品必须保留」要单独写一句**——不写，模型会把手机、机器人全删掉；
2. **「人物完整」要单独写一句**——不写，会出现断手、半张脸；
3. 算法提取和图像生成都试过之后你会发现：**生成优于提取**，提取只适合应急。

### 0.7 迭代节奏：先审已完成的，再下发修正

这个项目所有需求都是「迭代式修正」推进的：Agent 交一批 → 你看图 → 指出具体哪页哪里不对 → 下一批。给 Agent 下达修正指令时，用「预期 vs 实际」格式：

```
预期：s_chorus3 的歌词应该像示例 MP4 那样右缘竖排、逐字点亮。
实际：歌词跑到了左下角，且和人物同侧。
请只修这一个分镜，别的都不动。
```

### 0.8 别让 Agent 一次性「全片优化」

「把全片检查一遍顺便优化一下」是灾难指令。全片 187 秒、30+ 分镜，Agent 会改出十几个不可追溯的回归。正确做法：

- 修改前先让它跑 **帧差扫描**（见 15.2），只修扫描出的问题；
- 每修一个 bug，**只重渲受影响的时段**（`render.py video out.mp4 t0 t1`）验证；
- 全片重渲只在「一批修复全部确认后」做一次。

## 一、项目概述

- **曲子**：potatoになっていく / Wonderlands×Showtime（神代類・天馬司・鳳えむ・草薙寧々・初音ミク）/ Neru

- **技术形态**：纯 Python 程序化渲染。每一帧都由 GLSL shader + 2D 矢量绘制 + Live2D 模型 + SDF 文字实时合成，不存在任何一帧「素材片段」
- **美术路线**：铅格风纸底（方格纸纹理）+ 复古电影调色 + 全角色手绘线稿（由图像模型以活动卡面为参考生成）+ 复古剧院节目单式排版
- **代码规模**：约 4500 行（Python 2100 行 + GLSL 2400 行），零第三方运行时依赖（除 moderngl / live2d-py / numpy / Pillow / imageio-ffmpeg）

渲染器内部流程：每一帧 → Live2D 角色更新 → 背景 shader（纸底）→ 逐层矢量绘制（道具/线稿/文字）→ 后期 shader（调色/颗粒/晕影/转场混合）→ RGBA 写入 ffmpeg stdin → H.264 + AAC。

## 四、视觉体系（定稿，不要动）

### 4.1 铅格纸底

`shaders/paper.frag` 生成方格纸：34px 方格 + 每五格加重线，`uGrid` 控制浓度（0=关闭，1=全浓度）。全片默认 `grid=.55`，标题页降到 `.30`。纸色偏暖米黄（`.906, .875, .784`）。

### 4.2 复古电影调（FILM 基调）

`director/shots_new.py` 顶部定义，全片每个分镜的后期参数都从它派生：

```python
FILM = dict(uRetro=0., uSat=.92, uContrast=1.03, uGrain=.024, uVignette=.24,
            uCA=.35, uBloomAmt=.5, ...)
```

低饱和（.92）、轻微提对比（1.03）、细颗粒（.024）、弱晕影（.24）、轻微色差（.35）。黑场/回忆类分镜用 `uLift=.35～.5` 抬黑。**新分镜的返回 dict 必须以 FILM 为底**，不得使用 `POST_DEFAULT`（那是旧风格）。

### 4.3 线稿人物

- 所有角色均为手绘风线稿：白底黑线（墨色 `INK = (.098,.080,.062)`）。
- 线稿由图像模型以活动卡面为参考生成，存于 `work/lineart_src/`，命名 `{who}_{nn}.png`（`who` ∈ rui/tsukasa/emu/nene）。
- 介绍页肖像另有单张 `{who}.png`（`emu.png` 含熊猫，对应卡面「凤笑梦_122 骑上熊猫」）。

## 六、姿势库与出场规则

- 姿势库共 37 张实图（lineart_src 内另有变体共 98 文件）：rui 9 张、tsukasa 9 张、nene 8 张、emu 11 张。
- **每张都必须出镜**：`next_pose(who)` 按序号轮转，每换一个镜头走一步。
- **镜头内姿势锁定**：`held_pose(who, slot, gi)` 以 `(shot_id, who, slot, gi)` 为键缓存，镜头第一帧选定后整镜不变——这是「屏录闪动」bug 的修复，**绝不能回退成逐帧选姿势**。
- `actor(t, slot, h, ...)` 出当前歌手 + `ghosts=2` 张该角色其他姿势的残影（alpha .22），保证 37 张全用上。
- 硬约束：`h ≤ .52`（人物高不超过半屏），`cx ≤ W*0.40`（人物只在左半屏）。
- 校验工具：环境变量 `POSE_LOG=1` 渲染全片，统计每张姿势出场次数。

模板按**镜头**轮换而非按行，避免镜头中途版式跳变。**歌词与人物不得同侧是铁律。**

## 八、道具层（director/props.py）

每个分镜至少三件道具。全部函数一览（参数详见源码 docstring）：

|---|---|
| 舞台结构 | `curtain`（双侧幕布，可分别控制）、`spot`（聚光锥，预烘焙贴图防百叶窗纹）、`floor`（透视地板线）、`window`、`rain` |

**radar（学院倒计时扫掠）**——本片 0–3 秒领导片的招牌效果，最终版实现：

```python
props.radar(m, cx, cy, r, ang, a=.42, tails=30, span=.55)
# 余辉 = 约 50 根细射线从轴心扇形展开到指针身后，
# 透明度随角度 (1-f)^1.8 衰减，形成一片连续渐隐的楔形
# 不要用同心点阵做余辉——会有梳齿状条纹；不要用离散圈层——会有环状断裂
```

历史教训：`props.py` 曾出现 `ring`、`radar` **重复定义**（后者覆盖前者），导致改动「不生效」。改完没效果，先 `grep -n "def radar"` 查重。

## 十二、给 Agent 的常见任务速查（recipes）

**加一个新分镜**：在 shots_new.py 复制相邻分镜函数 → 改内容 → `add()` 挂时间轴与转场 → 检查时间轴无重叠 → 抽帧确认 FILM 基调、三件道具、歌词右缘。

**换某角色的某个姿势**：线稿图放 `work/lineart_src/{who}_{nn}.png`（nn 顺延），无需改代码（`pose_files` 自动枚举）。若要指定某分镜用某张，`actor(..., pose=k)` 显式传索引。

**改歌词版式**：只允许改 `lyrics()` 内五个模板分支的内部实现；改模板轮换逻辑（`_shot_id % 5`）前必须想清楚会连带影响姿势缓存键。

**加新道具**：props.py 加 `def xxx(m, ...)`，用 `_solid` / `seg` 矢量绘制（半透明叠加会百叶窗纹，大面积渐变必须预烘焙贴图，参考 `_spot_tex`）。

**改结尾署名**：`s_end` 内 `typo.display` 的字号与文案；文案新增字符先入 EXTRA_TEXT。

## 十三、工程约束与历史 bug 清单（每一条都是真实的坑）

1. **姿势逐帧跳变 → 屏录闪动**：`next_pose()` 曾在每帧调用。修复：`held_pose` 按镜头缓存。全片帧差扫描验证（中位帧差 0.75，孤立跳变 0）。**不可回退。**
2. **props.py 重复定义**：`ring`、`radar` 各定义两次，后者覆盖前者，改动静默失效。经验：改完没效果先查重复 def。
3. **日文假名乱码**：等宽 `f_mono` 无假名。含 `ord(ch)>0x2e80` 字符的串必须用 `f_dot`。
4. **uMask=3 是星形不是圆盘**：齿轮/钟面曾画成星星，改用圆形叠加或点环（`ring`）。
5. **聚光锥百叶窗纹**：半透明条带逐条叠加必然 banding，预烘焙渐变贴图（`_spot_tex`）。
6. **幕布合不拢/透字**：宽度 0.30W 不够，改 0.52W/侧；不透明度 0.996。
7. **歌词越界裁切**：上下按 `H*.87` 反算字号，右侧内移留边。
8. **38s 处歌词重复两遍**：该处是幕间标题，误挂了歌词；标题改「幕間」并 `ly=False`。
9. **网格转场黄色棋盘边**：mode 12 的琥珀色边缘归零，改墨色勾边。
10. **18 张线稿零出场**：`gen_ln` 原来只在介绍页各调一次。重构为 `gen_ln(who, k)` 走 `pose_files` 全量轮转 + `ghosts=2` 残影，37 张全部出镜。
11. **齿孔条压人物**：`sprocket()` 已置空（函数体直接 return），别复活它。

## 十六、渲染管线详解（一帧是怎么画出来的）

`MV.frame(t)` 是全片的心跳，每秒被调用 60 次。理解它，你才能知道「我改的东西在哪一层生效」。一帧的完整流程：

```
1. 找镜头      遍历 shots 表，找到 t0 ≤ t < t1 的分镜
2. 判断转场    若 t 落在镜头头部的转场窗口内：
                 前一镜画进 shotA fbo，当前镜画进 shotB fbo，
                 wipe.frag 以 uProg 混合两块纹理，转场参数取
                 「前半段用前一镜的 post、后半段用当前镜的 post」，
                 保证调色随转场平滑交接
3. 无转场      当前镜直接画进 scene fbo
4. 泛光        scene → 1/4 分辨率双向高斯两次迭代（bl1/bl2 乒乓），
               阈值 .75 只提亮高光
5. 后期        post.frag 一次性完成：调色、颗粒、晕影、色差、
               抖动、纸纹褶皱(uCrumple)、Letterbox、转场残留特效
6. 读回        out fbo → RGBA → ffmpeg stdin（GL 行序自下而上，vflip 矫正）
```

三个离屏目标值得记住：`tvscreen`（960×720，CRT 电视机画面用）、`shotA/shotB`（转场专用）、`bl1/bl2`（1/4 分辨率泛光乒乓缓冲）。**所有矢量绘制都走 `m.rect()` → 实例化矩形批次**，一个 draw call 画几千个矩形，这是道具层敢每帧画上千个元素的底气。

音频驱动在 `director/common.py::Audio`：预分析音源得到 onset 表，`pulse(t, 'kick')` 返回鼓点后的指数衰减值（0→1→0），分镜拿它去弹字体大小（`150 + 6*kick(t)`）、灯串亮度、纸屑爆发。**所有「踩点」效果都来自这一个函数**，不要自己算节拍。

## 十八、线稿生产流水线

姿势库从零到 37 张的过程，复刻如下（要扩充姿势库时照做）：

1. **选卡**：从活动卡面池挑姿势差异大的卡（站姿/坐姿/伸手/回头……），每人至少 8 张。
2. **生成**：图像模型按 0.6 节提示词模式逐张画线稿。**用多个子代理并行跑**，每个代理只管几张卡，交付时自带白底检查。
3. **验收**：每张过三关——人物完整（无缺件）、无背景残留、线条粗细与既有库一致。不合格退回重画，**不要手动修图**（手工修的线在动画里会显突兀）。
4. **入库**：命名 `{who}_{nn}.png` 顺延编号，白底黑线 PNG。
5. **全量出镜验证**：`POSE_LOG=1` 渲染全片，核对统计表每张 ≥1 次。

早期用算法提取（`line_art`）生产的线稿全部淘汰——梯度边缘无法区分「该留的头发丝」和「不该留的背景噪点」，`_salient` 连通域过滤也救不了。**生成优于提取，这是本项目花了一整轮迭代换来的结论。**

## 十九、逐幕设计解说（为什么长这样）

了解设计意图，才能在续作时不破坏它。

**领导片（0–3s）**：致敬胶片时代的学院领导片——倒计时数字、十字规线、扫掠雷达、胶片边码。它先告诉观众「这是一部『电影』」，为全片的复古剧院世界观定调。雷达余辉必须是连续渐隐的楔形（见第八章），任何「点阵感」都会破坏胶片颗粒的质感统一。

**标题页（3–5s）**：幕布半开 + 聚光 + 跑马灯 + 纸屑。所有元素都在说「剧场要开演了」。标题字号随鼓点呼吸（`150 + 6*kick`），这是全片第一次「踩点」，让观众建立「画面会跟着音乐动」的预期。

**介绍页（5–9s）**：每人 0.82 秒，快切。单张肖像 + 左下黑名牌 + 英文小字，像剧场节目单的人物页。轮流左右站位（`side` 参数）避免四连切呆板。

**段落 A（12s 起）**：叙事开始，分镜变长（2–5 秒），歌词进入右缘轮换。人物只出歌手（`cast(t)` 硬约束），器乐段只放道具——「画面即舞台，谁唱谁上台」的剧场逻辑贯穿全片。

**副歌（27–40s）**：呈现强度拉满——巨字、双层文字雨、全队上台、纸屑+音符+灯串全开。但**底层的纸格、FILM 调色、右缘歌词纹丝不动**：热闹只在内容层，语法层永远冷静。这是「复古电影感」不被狂欢场面冲垮的关键。

**回忆段（60–64s）**：`uLift=.5` 抬黑近似旧胶片褪色，道具换成时钟、雨、窗——用道具语义而不是滤镜贴纸来讲「过去」。

**结尾（89s+）**：署名压大字（46 号，64 号会左右裁切——节目单排版没有「居中缩放」的余地，字号是被版式反算的），幕布从两侧合拢把整部片「关」进剧场。没有谢幕辞，没有「幕」字——灯光熄灭本身就是谢幕。

## 二十一、FAQ

**Q：改了一个道具但画面没变？**
先查 props.py 有没有同名函数重复定义（教训 #2），再确认调用处的参数不是被分镜函数里的另一份调用覆盖。

**Q：新加的字显示不出来？**
EXTRA_TEXT 白名单没加该字符。SDF 图集按白名单建，白名单外的字静默消失，不报错。加完记得删 `work/cache` 里对应字体的缓存让它重建。

**Q：歌词为什么不用花哨的动画？**
歌词版式五模板按镜头轮换、镜头内锁死，是为了「版式不跳变」。点亮动画只发生在字级（逐字 timing），层级干净，才不抢人物和道具的戏。

**Q：为什么人物永远在左半屏？**
歌词右缘是全片恒定语法，人物在左是它的镜像平衡。打破任意一边，构图语法就散了。真需要人物居中的特殊页（如介绍页），用 `member_shot` 那种「居中大图 + 名牌」的独立模板，而不是修改全局约束。

**Q：渲染多少帧/秒正常？**
本机 NVENC 环境 130–195fps。低于 80fps 先查是否误开了逐帧选姿势（教训 #1 的变体）或某道具每帧在烘焙贴图。
